# TESTING.md — 手感验证与测试

## 两类测试

1. **公式正确性（客观）** — 可自动化，验证移动数学符合 spec。
2. **手感验证（主观）** — 只能由前职业选手试玩判断，是最终标准。

## 公式单元测试

`movement.gd` 是纯函数，可脱离游戏测试。建议用 GUT（Godot Unit Test）或简单的断言脚本验证：

- `accelerate`：给定静止状态 + wishdir，单 tick 后速度增量 = `accel * delta * wishspeed`（未超 add_speed）。
- `air_accelerate`：验证 wishspeed 被裁到 cap；验证速度已达 cap 时沿 wishdir 不再加速，但垂直于当前速度的 wishdir 仍能加速（air strafe 的数学本质）。
- `friction`：低于 stopspeed 时减速更快。
- `clip_velocity`：撞墙后法向分量被移除，切向分量保留。

## 客观参照

速度 HUD 给职业选手提供客观锚点：
- 直线跑 ≈ 320
- 一次完美 air strafe 连跳后速度应明显高于 320
- 这些数字职业选手心里有谱，是验证手感最快的方式

## 调参流程

1. 试玩 → 记录哪里不对（"急停太黏"/"连跳加速太慢"）
2. 回 `MOVEMENT_SPEC.md` 确认是公式错还是参数问题
3. 公式错 → 改 `movement.gd` 并补单元测试
4. 参数问题 → 调 `movement_params.tres`，运行时热调更快
5. 重复直到盲测通过

## 回归保护

每次锁定一个满意的手感版本，把 `movement_params.tres` 连同 commit 一起标记（git tag），方便日后对比"是不是改坏了手感"。
