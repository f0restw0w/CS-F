# ROADMAP.md — 路线图

> 一次只做一个 Phase。前一个 Phase 的验收标准没过，不许进下一个。
> 核心纪律：**先证明手感能做出来，再扩张范围。**

## Phase 0 — 移动控制器原型 【当前】

**目标：** 做出一个让前职业选手认可的 1.6 移动手感。这是整个项目的命门。

任务：
1. 搭 Godot 4 项目骨架，设 `physics_ticks_per_second = 100`。
2. 灰盒 dust2 地图：按 `docs/MAP_DUST2.md` 重建 de_dust2 的**完整布局**（出生点+中路+A区+B区+所有主要通道），纯灰盒（greybox），无贴图无模型。在熟悉的空间里测身法效率最高。**注意版权红线见下文及 MAP_DUST2.md。**
3. `MovementParams` 资源 + `movement.gd`：实现 accelerate / air_accelerate / friction / clip_velocity（严格按 `MOVEMENT_SPEC.md`）。
4. `player_controller.gd`：固定步长物理循环 + 跳跃 + bunnyhop（落地按跳跳过摩擦）。
5. `camera_controller.gd`：鼠标视角，捕获鼠标。
6. 调试 HUD：实时显示水平速度等。

**验收标准（全部由负责人主观确认）：**
- [ ] 直线跑速度稳定在 max_speed
- [ ] 急停干脆，不拖沓
- [ ] 能 bunnyhop 连跳保速
- [ ] 能 air strafe（空中靠鼠标+方向键加速并转向）
- [ ] 撞墙沿墙滑行保留切向速度
- [ ] **负责人闭眼也觉得"这就是 1.6"**

⚠️ 这个 Phase 可能需要反复调参迭代。手感不对就回到 `MOVEMENT_SPEC.md` 查公式，别将就。

## Phase 1 — 移动手感打磨

- 加蹲（duck）及 duck-jump
- 验证/还原 surf（斜面贴墙加速）
- 楼梯/台阶平滑上下
- 把所有手感参数调到负责人满意，**锁定** `movement_params.tres`

## Phase 2 — 武器系统（单机）

- 一把枪（建议先做 AK 或 M4 手感）
- 射击、换弹、后坐力、弹道扩散（CS 的 spray pattern 也是手感的一部分）
- 命中判定（hitscan）
- 占位音效/模型

## Phase 3 — 关卡与画质

- 一张可玩的灰盒图 → 逐步替换为现代 PBR 美术
- 现代光照（GI、阴影）
- 此阶段开始需要外部美术资产

## Phase 4 — 联机

- 网络架构（client-side prediction + server reconciliation —— 对移动手感至关重要）
- ⚠️ 移动的网络同步是难点：要在保证 1.6 手感的同时做好预测回滚。提前规划。
- 反作弊是长期工程，原型期不碰。

## 范围红线

- Phase 0/1 之前**不写**任何武器、联机、UI、美术代码。
- 任何"顺手加个功能"的冲动，先问是否服务于当前 Phase。
- 美术资产（模型/贴图/音效）全程由负责人外部提供，Claude Code 只用占位资源。

- de_dust2 的**布局/几何结构不受版权保护**，可以合法用灰盒重建（这正是 Phase 0 要做的）。受保护的是具体的美术资产（贴图、模型、地图文件）。
